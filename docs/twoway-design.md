## 0. 主題

平衡。玩家必須同時把投球與打擊撐在水準之上才留得住二刀流資格；
任何一側掉下去就被迫收斂成單刀，而且投在另一側的能力點不會退還。

## 3. 資料模型

### 為什麼用 `S.pos='TW'` 而不是另開 `S.twoWay` 旗標

全專案有 ~95 個 `S.pos==='P'` 分支散在 15 個檔案。新增第五個值會讓這些分支**明確走錯路**，
容易找、容易測；加旗標的話它們會**安靜地**把二刀流當成打者處理，bug 會延後半年才浮出來。

### 已經支援、不用改的

- `blankStat()`（`state.js:42`）本來就是投打欄位的聯集，`S.stats` **不用改 schema**。
- `S.log[]` 每列同時有 `p`（守位）與 `role`（SP/MR/CL），只是渲染時各挑一個。
- `S.roleYears` 與 `S.dposYears` 兩個都在，只是 `accStat()` 用 `else if` 二選一（要改成兩個都累積）。
- `addIntlStat()`、`capTeam()`、`salaryFor()`、`controlledAnnual()`、`injuryProb()`、`ui/traits.js` 完全與守位無關。

### 要新增的

- `POS_AB.TW = ['sta','vel','ctl','brk','con','pow','spd','eye']`
- `newState()` 的 TW 初始能力／潛力分層表（投手是 4 階、打者是 4 階，TW 要自己一組 8 項的）
- `S.potSum0` 的 TW 門檻（`retire.js:616` 努力仔現在只有投手 237／打者 469 兩個數字）
- 一個獨立的**投球出場計數**（見 §6 的 TJ 風險）

## 4. 每季的投打比重

現在的 `投球規劃`（全力投／普通投／養生球 → `S.effort`）是投手專屬，
掛在 `phases.js:85-94`，餵給 `season.js:413`（成績加成）與 `injury.js:11`（TJ 倍率）。

二刀流要換成一張**決定 `sta` 怎麼分配給 IP 與 PA** 的面板：多投就少打，多打就少投。
這樣「平衡」不只是配點時的一次決定，而是每一季都要重做的取捨，
也直接影響獎項門檻（投手三冠要 IP、打擊三冠要 PA、新人王兩邊都有工作量門檻）。

檔位還沒定。方向是三到四檔，兩端各自能單獨衝獎項、中間檔兩邊都拿不到王但總價值最高。

## 5. 生涯評價與名人堂（最難的一塊）

`careerScore()`（`career.js:66-69`）就一行 `if(S.pos==='P')`。投手分與打者分是**分開校準**的
（打者那條還乘了 0.67 做跨位校正），而 `TIER_TH` / `HOF_TH_K` / `LEAGUE_K`
都是用母體模擬反解出來的常數。

**直接把兩邊相加，二刀流會變成無腦進名人堂；不加又完全不划算。**

需要：
- `tierOf()` 的 `posKey` 新增 `'TW'`，在 `data/economy.js:87,118` 補 `LEAGUE_K.TW` 與 `HOF_TH_K.TW`
- `honorScore()` 現在是「每年取最高一項」——二刀流同年拿下最佳投手＋最佳打者會被吃掉一座，要放行
- TW 的守位調整**不要沿用 DH**（`POS_ADJ_RUNS.DH = −14`、`POS_TIER_K.DH = 1.13`，全聯盟最重的懲罰）；
  沿用會讓二刀流被罰兩次

**校準方法**：沿用先前的 headless 模擬 + `EVENT_W × ALLOC_W` 重新加權，
目標是把 TW 的名人堂率壓在 15% 錨點附近，同時確認它既不是支配解、也不是廢棒。
這一步不做，功能就是壞的。

## 6. 掃出來的風險清單

依嚴重度排序。實作時逐條劃掉。

### 結構性（要重寫）

1. **`st.G` 一個欄位兩種意思。** 投手的 `G` 是先發／後援場次，打者的 `G` 是出賽數，
   `simSeason()`（`season.js:60`）只回傳一個 `st`。二刀流需要兩個獨立的出場預算，
   而且要用同一份 `sta` 去付。
2. **`ovr()`（`ability.js:120`）是全域關卡**：升降級、國際賽徵召、選秀輪次、旅外門檻、
   引退底線全部走它。TW 需要一個合併算法，否則打擊對每一道關卡都是隱形的。
3. **`dposReview()`（`ability.js:40-106`）在投手分支 `return`**，二刀流會拿不到 `dpos`。
   要改成 role 與 dpos 兩段都跑。
4. **`abCost()` / `addAb()` / `addAbStat()`（`ability.js:154,179,199`）用 `const isP=S.pos==='P'`
   決定成本曲線**——要改成**看 key**，不是看 pos：`vel/ctl/brk` 走投手陡曲線，
   `con/pow/eye/spd` 走打者曲線，`sta` 走打者曲線。同一條公式抄了三份，改的時候三份都要同步。
5. `seasonSalaryRating()` / `seasonGrade()`（`season.js:216,243`）各自 `if/else` 回傳一個數字，
   沒有地方把投球價值＋打擊價值加起來。`seasonGrade` 還驅動升降級與明星級年資。

### 會安靜出錯（最危險）

6. **`tjAccrue()`（`injury.js:10`）用 `isSP()?st.IP:st.G` 當工作量**——二刀流的 `st.G`
   含打擊出賽，後援累積會被灌爆。**一定要換成獨立的投球出場計數。**
7. **季前衰退 `phases.js:27-36` 是 `POS_AB[S.pos].forEach`**——沿用 `POS_AB.P` 的話
   二刀流的打擊永遠不會衰退。`injStatLoss()`（`injury.js:155`）同理。
8. **`eventTarget()`（`events.js:71`）** `ev.target in S.ab ? ev.target : pick(POS_AB[S.pos])`
   ——打擊卡的 `target:'con'` 若 `S.ab` 沒有該鍵會靜默 fallback 成隨機投手屬性。
9. `accStat()`（`season.js:314`）的 `else if` 讓 `roleYears` 與 `dposYears` 只會累積一邊。

### 閘門放寬（改條件、邏輯不動）

10. `eventEligible()`（`events.js:36-49`）：`role==='B'` 排除 P 和 C、`role==='F'` 排除 P。
    TW 要能同時吃投手卡與打者卡。改完要驗 `availableEventCombinations()` 三條路線都還湊得出組合。
11. `awards.js` 的兩大區塊分別包在 `if(S.pos==='P')`（124-166）與 `if(S.pos!=='P')`（167-235）。
    拆開後**各側的工作量門檻要保留**，否則二刀流會用半套出場數領雙獎。
    `rookieWorkloadEligible()`（33-41）與 `mvpQual`（237-271）也要 TW 分支。
12. `termParams()`（`contract.js:429`）與 `faMarket()`（`contract.js:564`）
    各有一份 `S.pos==='P'?pitcherContractCap():15`——建議 TW 走 15（大谷那張是 10 年）。**兩處都要改。**
13. `movement()`（`phases.js:311-326`）的降級保護只看一側，要改成任一側夠好就保護。
14. `intl.js:79-104` 的 `intlSt` 二選一，要合併。

### 顯示層（廣但淺）

15. `ui/alloc.js:49` `POS_AB[S.pos]` 決定顯示哪幾列——8 列排版要看一下。
16. `ui/dom.js:273-298` `secLog()` 六欄表頭投打二選一，行動版還有 `drop[]` 遮罩。
17. `ui/retire.js` 四個資料建構器（`rpCumData` / `rpIntlData` / `rpProData` / `rpSalaryData`）
    各自 `const isP=...` 回傳完全不同的形狀；再加結算表頭、四段引退結局文案、努力仔門檻。
18. **`ui/share-image.js:279-280,296-297` 的年表欄位是硬幹在 820px 畫布上的固定像素寬**
    （投 12 欄、打 15 欄）。二刀流 ~20 欄放不進去——要改成一季兩列（投／打）或加切換。
    這是唯一一個「不是改 code 就能解決」的地方。
19. `playerType()`（`ability.js:135`）要一個二刀流稱號；`dom.js:199` 的記分板 chip
    其實已經會把 `dpos` 和 `role` 串在一起（「右外野手・先發」），幾乎是現成的。

## 7. 事件卡：XLSX 要怎麼填

`src/data/events.js` 由 XLSX 的「完整事件表」產生，目前 **92 張，ID 1~92**（93~96 仍空缺）。
新卡請從 **ID 97** 開始編。

### 欄位

| 欄位 | 必填 | 允許值 | 說明 |
|---|---|---|---|
| `id` | ✓ | 整數 | 從 97 起。不可與現有重複。 |
| `n` | ✓ | 文字 | 卡名，會顯示在事件標題「事件｜類別｜卡名」。 |
| `times` | ✓ | `ALL` / `HS` / `U` / `AMA` / `MINOR` / `PRO`（可多選） | 可出現的生涯階段。 |
| `scope` | ✓ | `*` / `CPBL` / `NPB` / `MiLB` | 限定聯盟；`*` 為不限。 |
| `role` | ✓ | `*` / `P` / `B` / `C` / `F` / **`TW`** | **二刀流專屬卡填 `TW`。** |
| `category` | ✓ | `training` / `endorsement` / `encounter` | 訓練／代言／遭遇。 |
| `intro` | ✓ | 文字 | 引言，接在卡名下方；句尾通常不加句號（後面接選項）。 |
| `target` | ✓ | `sta`/`vel`/`ctl`/`brk`/`con`/`pow`/`spd`/`eye`/`rand` | **二刀流卡只能用這 8 項或 `rand`**——填 `rng`/`fld`/`arm`/`cat` 會靜默失效。 |
| `maxAge` | | 整數 | 選填，超過此年齡不再抽到。 |
| `note` | | 文字 | 給人看的備註，不進遊戲。 |

### 三個選項的文字

每張卡要 **9 格**：`bold` / `norm` / `safe` 各一組 `label`（按鈕文字）、`good`（成功）、`bad`（失敗）。

- `bold` 全力一搏：成功率最低、獎勵最大
- `norm` 普通應對
- `safe` 保守：成功率最高、獎勵最小

（成功率由 `eventPlan()` 統一計算，不寫在卡上。）

### 有傷病風險的選項

若某個選項的**失敗文本描述了受傷／疼痛／過勞**，要另外登記到 `EVENT_INJURY_BAD_MODES`
（`data/events.js:17-23`），格式 `卡ID:['bold','norm','safe' 之中會受傷的]`。
XLSX 裡請在 `note` 欄註明「傷病：bold, safe」之類，我來搬進表裡。

### 建議張數

現有各類別可用卡數（`*` 為所有人都抽得到）：

```
training    * 9 ｜ P 18 ｜ B 10 ｜ C 5 ｜ F 1
endorsement * 10 ｜ B 4          （沒有投手專屬代言卡）
encounter   * 17 ｜ P 4 ｜ B 7 ｜ C 7
```

二刀流會同時吃到 `*` ＋ `P` ＋ `B`，牌庫本來就夠厚，
所以 **`TW` 專屬卡是拿來做味道的，不是拿來補數量的**——
每個類別 2~4 張就夠，重點放在只有二刀流會遇到的處境
（休息日要不要上場打、投完隔天的打擊、兩邊教練搶人、被質疑分心、專守一邊的誘惑……）。
